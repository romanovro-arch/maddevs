# MadEvents — Сервис регистрации на мероприятия

Высоконагруженный сервис регистрации и контроля доступа на мероприятия с защитой от **Race Condition**, автоматическим **листом ожидания (FIFO)**, однократным **чекином** и **live-дашбордом организатора**.

---

## Архитектура проекта

```text
maddevs/
├── backend/                   # Бэкенд на Bun + Hono + SQLite + Drizzle ORM
│   ├── src/
│   │   ├── db/                # Схема БД (events, registrations, tickets, mail_logs)
│   │   ├── services/          # Транзакционная логика, чекин, рассылка, планировщик
│   │   ├── routes/            # REST API эндпоинты
│   │   ├── ws/                # WebSocket стриминг для live-счётчика
│   │   └── index.ts           # Сервер Hono на Bun
│   └── tests/
│       └── concurrency.test.ts # Тест на 20 одновременных запросов на 2 места
│
└── frontend/                  # Клиент на Next.js (App Router) + shadcn/ui
    ├── apps/web/              # Next.js приложение
    │   ├── app/               # Страницы: события, чекин, дашборд, билеты
    │   ├── components/        # UI-компоненты (Билет с QR, Dev Mailbox, модалки)
    │   └── hooks/             # WebSocket-хук для live-статистики
    └── packages/ui/           # Пакет дизайн-системы shadcn/ui на Tailwind CSS v4
```

## Реализация ключевых требований

1. **Защита от состояния гонки (Race Condition)**:
   - При одновременной регистрации нескольких человек на последнее место бронирование выполняется в атомарной транзакции SQLite (`db.transaction`).
   - Ровно один запрос получает статус `CONFIRMED` и билет, остальные автоматически уходят в `WAITLIST`.
   - Проверено стресс-тестом: `bun run test:concurrency`.

2. **Лист ожидания (FIFO) и авто-продвижение**:
   - Когда участник отказывается от места (`POST /api/registrations/:id/cancel`), первый человек из очереди автоматически переводится в подтверждённые участники, для него генерируется билет и отправляется письмо.

3. **Защита от повторной регистрации на один email**:
   - Композитный индекс `(event_id, email)` исключает дублирование места.

4. **Однократный чекин и Live-счётчик**:
   - На входе билет гасится ровно один раз. При повторном вводе система выдает отказ с указанием точного времени первого прохода.
   - Счётчик пришедших у организатора обновляется **в реальном времени по WebSocket** без перезагрузки страницы.

5. **Напоминание ровно за 24 часа**:
   - Фоновый планировщик с транзакционной фиксацией флага `reminder24hSent`, исключающий повторную отправку.

6. **Уведомление о переносе даты**:
   - При смене даты организатором все участники (`CONFIRMED` и `WAITLIST`) получают автоматическое письмо с новой датой.

7. **Виртуальный почтовый ящик (Dev Mailbox)**:
   - Встроенный в интерфейс виджет для мгновенного просмотра отправленных писем и перехода к билетам.

## Быстрый запуск

### 1. Запуск бэкенда
```bash
cd backend
bun install
bun run seed         # Генерация тестового мероприятия с заполненными местами
bun run dev          # Запуск сервера на http://localhost:3001
```

### 2. Запуск фронтенда
```bash
cd frontend
bun install
bun run dev          # Запуск Next.js на http://localhost:3000
```

### 3. Запуск тестов конкурентности
```bash
cd backend
bun test tests/concurrency.test.ts
```
